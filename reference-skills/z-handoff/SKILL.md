# 交接未完成任务

本 Skill 提供保存一次上下文切换所需最小恢复信息的方法。交接不是主开发阶段、长期状态、阶段报告或第二份规格；任务仍由恢复后的 Agent 依据原目标与授权继续。

## 判断是否需要

- 任务已经满足完成标准时，交付完成结果，不创建交接。
- 当前上下文能够继续时，不为了形式创建交接。
- 只有任务未完成且必须更换 Agent、会话或上下文时才继续。
- 用户只要求查看进度时，直接报告进度，不用交接文件代替回答。

## 收集恢复信息

引用已有规格、任务、设计、ADR、提交和差异，不复制正文。只记录：

1. 当前任务、目标范围和相关事实来源的稳定引用；
2. 已完成和尚未完成的内容；
3. 基准提交、分支、工作区状态和属于当前任务的未提交文件；
4. 最近实际运行的验证或反馈命令及结果；
5. 继续工作必需、但尚未进入正式事实来源的已确认决定；
6. 新上下文最先执行的一步。

疑难 Bug 额外引用稳定反馈、当前复现率、已证伪假设和临时探针位置。不要保存长篇思考、猜测、完整聊天、完整差异或可从仓库直接恢复的信息。

## 保存与核验

优先使用项目已有且后续上下文可发现的临时交接位置，但只有现有项目修改授权覆盖时才写入项目。否则使用操作系统临时目录，并在结果中报告绝对路径。文件名包含任务标识，不能覆盖其他交接。

写入前删除 API Key、密码、令牌、真实个人数据和敏感载荷；必要时只引用安全存储或脱敏 fixture。核验路径、提交、命令和未提交文件仍真实存在，再报告交接位置、恢复第一步、继承的授权范围和仍需用户决定的事项。

恢复后不保留常驻监督机制。任务完成时，Agent 可以清理自己创建且已失效的临时交接；项目内记录的删除或归档仍服从项目约定和对应修改授权。
