# 测试驱动开发

本 Skill 提供一个行为切片的红、绿、重构方法，并把结果交给 Agent；整项任务仍由 Agent 负责。

## 继承任务边界

- 从调用者继承当前行为、修改授权和验证要求，不自行扩大任务范围。
- 直接调用时，只有用户明确要求修改代码或测试才进入红绿循环；只读请求只给出测试策略，不写文件。
- 本 Skill 不执行整体代码评审、任务级提交、发布或完成声明。

## 选择入口

- **新增行为**：红灯 → 最小绿灯 → 全绿下重构。
- **Bug 修复**：先建立能稳定捕获用户症状的失败回归测试，再修复。
- **缺保护重构**：先写并运行通过的刻画测试，锁定现有行为，再小步改动并保持绿色。
- **视觉、配置或文档**：使用构建、静态、视觉、实际运行或其他匹配证据，不为了形式制造测试文件。

无法合理自动化时说明原因、替代证据和验证盲区。只有风险不可接受或判断标准需要用户决定时设置确认点。

## 选择测试接缝

读取 [`../_shared/codebase-design.md`](../_shared/codebase-design.md)，在能够观察真实行为的最高公共接口测试。调用者与测试跨越同一接缝；接缝选择会改变公开契约、范围或成本时才请用户确认。

- 优先真实代码和本地可替代依赖；
- 只在真实外部边界 mock，不 mock 内部协作者；
- 测试名称描述领域行为；
- 期望值来自规格、已知例子或独立事实，不用与实现相同的算法重新计算；
- 不测试私有方法、SQL 调用次数或只为测试新增的生产接口。

## 红绿重构循环

1. 写一个行为测试并实际运行。
2. 确认它因目标行为缺失而失败，而不是语法、fixture 或环境错误；若意外通过，先判断行为是否已存在或测试是否无效。
3. 写通过当前测试所需的最小实现。
4. 实际运行到绿色，并检查没有掩盖失败或警告。
5. 在保持绿色时整理命名、重复和结构，再运行测试。
6. 一次只推进一个纵向行为切片，然后根据新信息选择下一项。

把当前切片、执行过的命令、红灯原因、绿灯结果和未覆盖风险交给 Agent 整合。测试通过只证明已覆盖行为，不自动证明整项任务完成。
