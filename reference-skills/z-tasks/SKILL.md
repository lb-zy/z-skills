# 拆分交付任务

本 Skill 提供把已确认规格转换成一组有界、可验证纵向成果的方法，结果由 Agent 用于后续工作。它不包含任务实施，不扩大文件修改、外部写入、实施或发布授权，也不维护统一任务状态。

## 核对边界

1. 读取已确认规格、必要设计、项目规则和足以判断切片边界的现有代码，使用项目领域语言；不根据一段未确认想法直接造任务。
2. 确认规格的目标、范围、关键规则和整体完成标准已经由用户确认。规格未确认或存在会改变切片的阻塞取舍时，把缺口交回 Agent；已有请求覆盖形成规格时，Agent 可以先应用 `z-spec`。
3. 将任务拆分、任务写入和实施授权分开判断。用户要求拆分时可以在对话中交付任务；仅写出 `$z-tasks`、确认规格或接受拆分，不单独授权写文件、创建外部 Issue、修改任务状态或开始实施。
4. 只有现有授权覆盖时，才写入项目已选定的唯一任务事实来源。外部任务平台还必须有明确或持续有效的外部写入授权、目标项目和必要权限；不同时维护互相竞争的完整副本。
5. 从当前规格继承范围和完成标准，不新增功能，也不把实现偏好提升为任务要求。

## 形成纵向切片

1. 从用户可观察成果或独立系统能力切分，优先让第一个最小切片证明一条真实路径。
2. 判断每项是否能由一个干净上下文可靠实现、验证和评审。过大时继续按独立成果拆分；过小且不能单独验收时合并。
3. 只包含成果真正需要的技术层，不把纵向切片机械解释为每项都必须修改数据库、接口和界面。
4. 记录真正阻塞开始或完成的依赖。共享文件、潜在冲突或推荐顺序不自动构成业务阻塞；检查依赖图不存在循环。
5. 让测试、构建、视觉、性能、安全或迁移验证跟随对应成果进入完成标准，不创建最后统一补测试的水平任务。
6. 普通重构先建立新边界并迁移一条真实调用链，再分批迁移其余调用者。宽范围机械迁移使用 expand-contract：先兼容新旧形式，再按可保持基线绿色的批次迁移，最后在全部调用者完成后移除旧形式。

## 每项任务的最小内容

每项任务只记录执行者无法可靠自行恢复的约束：

1. 要产生的可观察成果；
2. 包含范围和明确排除项；
3. 可验证的完成标准；
4. 真正的阻塞依赖；
5. 相关规格、设计或原型的稳定引用；
6. 必须执行的特殊验证。

描述结果和约束，不预定文件、类、函数、代码片段、逐步方案或提交序列。实现细节只有在规格已经固定为外部契约或迁移约束时才保留。

## 检查并交付

1. 先形成完整拆分，再检查每项整体完成标准都被覆盖且只被放在最合理的任务中；不得遗漏、重复验收或加入规格外能力。
2. 检查每项任务在其依赖完成后可以独立进入、实现、验证和评审，并能以绿色基线结束。
3. 按现有授权在对话、本地唯一事实来源或明确的外部任务平台中交付；没有相应写入授权时保持只读，只呈现拆分结果。
4. 指出当前无阻塞、可以开始的任务和仍需用户决定的真实歧义，不增加固定粒度审批。
5. 把结果交给 Agent。已有实施授权明确覆盖某项任务时，Agent 可以随后选择 `z-implement` 或匹配方法；没有实施授权时只交付任务。全部任务完成且已有整体验收请求时，Agent 可以选择 `z-verify`，不要求用户为了形式重复输入 Skill。

## 完成条件

只有确认规格的完成标准已经被一组有界纵向任务完整覆盖、依赖关系可执行、每项任务都能由干净上下文独立验证，并且结果已在授权范围内交付，才结束本 Skill。任务拆分完成不等于任务已创建、已领取、已实施、已验收或已发布；这些事实只能由对应行动和证据产生。
