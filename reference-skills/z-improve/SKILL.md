# 调查代码库改善候选

本 Skill 提供调查并推荐代码库改善的方法，不把偏好包装成证据，也不修改产品代码或设计正式接口。结果由 Agent 用于当前任务；它不建立长期改善队列。

## 调查

1. 明确调查范围；用户没有方向时，从近期频繁改动、缺陷集中、测试困难或理解成本高的区域开始。
2. 读取适用领域词汇、ADR、项目规范、相关调用链和现有测试。
3. 需要判断模块、接口或测试接缝时读取 [`../_shared/codebase-design.md`](../_shared/codebase-design.md)。
4. 寻找可观察摩擦：同一规则散落、改一处牵动无关文件、浅层转发、双向依赖、事实来源重复、测试必须穿透内部或删除测试仍保有等价保护。
5. 对每个候选核实真实调用者、变化频率、影响、风险和现有保护；不以代码行数、流行架构或个人审美排序。

## 候选报告

每项候选包含具体证据与位置、预期价值及受益者、建议范围与排除项、主要风险、验证要求和匹配的后续能力。只保留证据与价值都能说明的候选；调查过大时先缩小，不自动升级为全库审计。

## 结束边界

给出按价值、风险和前置条件排序的候选并推荐一项。追问理由、补充症状、反对排序或表达一般改善意愿仍属于调查，不构成修改授权。

用户明确选择待实施候选时，该选择形成一个新的具体要求；若原发言同时明确要求实施且范围足够，Agent 可以继续应用 `z-architecture`、`z-tech`、`z-implement` 或其他匹配方法。否则只交付候选和下一步，不在本 Skill 内设计接口或实施重构。
