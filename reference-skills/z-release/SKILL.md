# 发布到指定目标

本 Skill 提供一次已授权发布从目标核对到真实位置验证的完整方法。发布是可选行动；Agent 始终是执行者，本方法不扩大成果、目标、受众、凭据、修改或发布授权。

## 核对边界

1. 综合完整对话、项目规则、验收证据和发布说明，明确要送达的成果、精确版本、目标位置、受众、成功标准与允许影响。
2. 将 Skill 调用与行动授权分开判断。用户明确要求把具体成果发布到具体目标，或当前持续任务已明确包含该目标时才执行发布；仅写出 `$z-release`、确认发布方案、完成本地实现或通过验收，都不单独构成发布授权。
3. 确认成果已经具备与发布风险相匹配的验收证据，工作区和待发布版本一致。证据不足时停止发布；已有任务范围覆盖补充验收时，由 Agent 先应用匹配的验收方法，完成后再继续发布。
4. 读取项目原生发布命令、CI、配置、迁移、监控和回退方式；不凭记忆构造命令，不把提交、PR 或分支合并误当成产品已经发布。
5. 核对运行环境的技术权限和凭据是否可用。发布授权不能替代 Codex 权限、平台确认或第三方访问能力；凭据不得读取到对话、打印或写入仓库。
6. 目标特有的托管或包管理 Skill 只作为 Agent 在当前发布范围内应用的方法，不改变发布目标；Agent 负责整合这些方法和结果。

## 判断是否适用

只有同时满足以下条件才继续：

- 成果和精确版本可识别，并已有足以发布的验收证据；
- 发布位置、环境或制品目录明确，成功标准可以在真实目标上观察；
- 当前用户发言或持续任务明确授权了这次发布及其影响范围；
- 项目存在可核对的发布方式，必要凭据和技术权限可取得；
- 目标影响、失败状态和恢复方式已经清楚到可以安全行动。

任一条件失效时保持只读，报告缺少的目标、授权、证据、权限或恢复信息。用户显式指定但不适用时，应用本节完成边界判断，不静默发布到猜测的默认环境。

## 处理高影响发布

影响真实用户、执行生产迁移、覆盖现有版本、造成停机或难以撤销时，在动作前集中核对目标、版本、影响、备份、回退和停止条件。当前用户发言已经明确授权同一具体高影响动作且上述信息齐备时，不重复索要形式确认；任何会改变这些内容的缺口都必须由用户决定。

## 完成发布闭环

1. **发布前检查**：验证成果、版本、配置、目标、权限和验收证据仍有效；记录发布前目标状态和可恢复基线。
2. **选择项目原生路径**：使用项目已有命令、CI 或适用平台工具；按真实目标决定步骤，不绑定特定托管商、包仓库或 Git 流程。
3. **控制每步影响**：为关键步骤明确预期结果、失败停止条件和恢复动作。数据变化先核对备份、兼容顺序、回退触发和不可逆变化的恢复路径。
4. **执行并等待终态**：只在授权范围内操作，读取完整输出和异步状态。失败或状态未知时停止、恢复或执行既定回退，不带着未知状态继续扩大影响。
5. **验证真实目标**：命令成功不等于发布完成。直接从用户将访问的位置验证精确版本、健康状态和关键冒烟路径；本地制品实际安装或启动，软件包从目标仓库安装，网站或服务访问真实 URL。
6. **形成结论**：报告发布版本、实际位置、执行方式、真实目标证据、迁移与回退状态、已知风险和验证盲区。失败时报告当前真实状态及已执行的恢复动作，不用“应该可用”作结。

## 完成条件

只有目标位置确实包含预期版本、关键冒烟路径通过、目标状态明确且迁移或回退风险已处理，才声明发布完成。发布完成后不自动扩张到其他环境、受众、分支、PR、合并或后续版本；这些行动分别服从用户授权和项目约定。
