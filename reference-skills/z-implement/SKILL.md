# 实现并验证有界任务

本 Skill 提供一项明确软件改动从接手到本地可交付的完整实现方法。Agent 始终是执行者；本方法不扩大目标、修改授权、提交授权或发布授权。

## 核对边界

1. 综合完整对话、项目规则、相关规格或设计、现有代码、测试和工作区状态，确认目标结果、范围、排除项、关键行为、约束与完成依据；不以最近一句替代完整任务。
2. 将 Skill 调用与行动授权分开判断。用户明确要求实现、修改或重构，或当前任务已有持续修改授权时才修改项目；仅写出 `$z-implement`、确认理解或认可方案，只指定方法，不单独构成修改授权。
3. 只有会改变目标行为、范围或验收依据的缺口，才由 Agent 应用 `z-clarify`；共同理解确认前不修改项目。能够从代码和环境查明的事实自行核对。
4. 记录 Git 基准和已有工作区改动及其归属；无法安全区分时停止写入并说明所需决定，不覆盖、回退或混入他人改动。
5. 需要其他专业方法时，由 Agent 根据实际问题选择并整合。被应用的 Skills 继承当前目标、范围、授权与验收要求。

## 判断是否适用

只有同时满足以下条件才继续：

- 用户要求产生软件项目改动，而不是只讨论、设计、分析、诊断或评审；
- 预期结果和完成依据足够明确，剩余问题能够在现有授权内由 Agent 从环境查明；
- 工作能够作为一次有界任务推进，不依赖先建立多会话规格或拆分多个独立交付；
- 当前工作不是缺陷修复；可稳定复现的 Bug 应使用 `fix-bug`，原因不明、间歇、性能或首次修复失败的问题应使用 `z-debug`；
- 没有尚未确认且会实质改变交付结果的产品、界面、架构或技术取舍。

任一条件失效时停止使用本方法，说明 `z-implement` 不再适用。已有授权覆盖后续工作时，由 Agent 改用匹配的 Skill 或直接处理；需要改变交付物、接受标准或影响范围时请求用户决定，不要求用户为了形式重复调用 Skill。

## 完成交付闭环

1. **建立基线**：读取实现入口、相关约束和现有验证，确认当前行为与任务范围；对依赖、工具和环境做足以开始工作的预检。
2. **选择切片**：从最小可验证行为开始，保持每次改动只服务当前结果，不顺带处理无关重构或新需求。
3. **应用专业方法**：新增可自动验证的行为或缺保护重构时，由 Agent 应用 `z-tdd`；界面、架构、技术或外部事实存在真实局部决策时，按需应用对应 Skill，不复制其方法。
4. **实现并读取反馈**：完成当前切片，立即运行相关测试、类型、静态、构建、视觉或运行检查，读取真实输出后决定下一步；失败时定位本次改动与既有问题的边界。
5. **扩大验证**：重复小切片，并按改动风险扩大到相关模块和用户路径；不机械要求与任务无关的全量检查。
6. **质量评审**：由 Agent 检查要求符合度和工程质量。中大型或高风险改动应用 `z-code-review`；小型低风险改动可以直接自查。修复所有阻断交付的问题并重跑受影响验证。
7. **交付结果**：逐条对照完成依据，报告实际改动、执行过的检查及结果、未解决问题和验证盲区。只有证据支持时才声明完成。

## 完成条件

只有目标行为已经实现、相关验证通过、评审没有未解决的阻断问题，并且验证盲区均已如实说明，本次实现方法才算完成。是否创建提交由用户要求和项目约定决定；修改授权本身不自动授权提交、推送、创建 PR、合并、部署或发布。任务变成多会话工作时，只记录恢复所需的最小事实，不建立另一套长期状态。
