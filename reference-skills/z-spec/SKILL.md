# 形成共享规格

本 Skill 提供把分散决定收敛为一份经用户整体确认共享规格的方法。Agent 始终是执行者；本方法不扩大目标、文件修改、外部写入、实施或发布授权。

## 核对边界

1. 综合完整对话、项目规则、既有需求与设计、研究或原型结论、领域词汇、ADR 和相关代码事实，确认本次规格服务的整体结果与后续使用者；不以最近一句替代完整工作。
2. 将 Skill 调用、规格确认和行动授权分开判断。用户要求形成规格时可以在对话中交付内容；仅写出 `$z-spec` 或确认规格，不单独授权修改项目、写入外部平台、开始实施或发布。
3. 只有当前请求或持续任务已经包含对应写入授权时，才把规格写入项目现有的唯一事实来源。没有写入授权或没有合适事实来源时，在对话中交付，不为使用本 Skill 新建管理体系。
4. 区分已确认决定、可核对事实、假设和开放问题。会改变目标、范围、规则或完成标准的阻塞性取舍，由 Agent 应用 `z-clarify` 或适用的产品、界面、架构、技术等 Skill；不能在规格中替用户决定。
5. 需要其他专业方法时，由 Agent 选择并整合；被应用的 Skills 继承当前目标、范围和授权。

## 判断是否适用

只有同时满足以下条件才继续：

- 工作跨越多个独立交付或多次上下文切换，需要稳定的共同依据；
- 已经存在足以复述整体目标、范围和关键规则的决定，剩余缺口可以明确列出；
- 本次交付目标是形成共享规格，而不是立即实现一个单项改动或拆分任务；
- 规格能够用可观察结果描述，不需要先编造尚未作出的产品或技术选择。

任一条件失效时停止使用本方法并说明原因。用户显式指定但不适用时，应用本节完成边界判断，不静默改用其他 Skill；已有目标和授权覆盖后续澄清或设计时，由 Agent 选择相应方法。

## 形成规格闭环

1. **建立依据**：按“已确认决定、项目事实、假设、开放问题”整理输入，解决矛盾并删除已被后续决定推翻的内容。
2. **编写紧凑规格**：只保留后续交付共同依赖的目标与预期结果、包含范围与排除项、关键行为与规则、跨任务共享决定、可观察整体完成标准、外部约束、主要风险和非阻塞待核实事实。
3. **保持实现中立**：描述必须满足的结果和约束，不写长用户故事、对话过程、逐文件改动、函数名、代码片段、详细施工步骤或交付任务。随时可从代码查明且不影响共同理解的事实只保留稳定引用。
4. **检查可执行性**：检查遗漏、矛盾、范围蔓延和不可测试表述；按实际风险检查权限、重复、并发、失败、撤销、时间边界与组合规则，不机械扩展无关章节。
5. **整体确认**：集中呈现目标、范围、关键规则、完成标准、主要风险和仍需接受的假设，请用户整体确认一次。用户补充或纠正后更新同一份草稿并重新确认，不把局部认可误当成整份规格获确认。
6. **交付确认版本**：明确标注确认状态，并按现有授权在对话或唯一事实来源中交付。没有授权时不创建文件、Issue、任务状态或其他外部记录。
7. **返回 Agent**：报告仍未阻塞的开放事实和可继续的下一类工作。原请求已经包含任务拆分时，规格确认后 Agent 可以应用 `z-tasks`；否则只交付规格，不要求用户为了形式重复输入 Skill，也不自动开始实施。

## 完成条件

只有用户已经整体确认规格、阻塞性矛盾与取舍均已解决、后续上下文能够仅凭该规格理解共同目标，并且确认版本已在授权范围内交付，规格形成才算完成。规格确认只确认交付依据；任何项目修改、外部 Issue 创建、实施、提交、发布仍分别服从用户授权和项目约定。
