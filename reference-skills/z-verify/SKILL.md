# 验收组合交付

本 Skill 提供多项已完成软件工作组合后的整体验收方法。Agent 始终是执行者；本方法默认保持只读，不扩大修复、任务状态、提交或发布授权。

## 核对边界

1. 综合完整对话、项目规则、已确认规格、交付任务及完成证据、相关设计和已知限制，确认本次要验收的整体结果与比较基线。
2. 将 Skill 调用与行动授权分开判断。用户明确要求验收，或当前持续交付授权包含整体验收时，可以运行非破坏性的测试、构建和实际路径检查；仅写出 `$z-verify` 不授权修改实现、任务状态或外部系统。
3. 确认规格已经确认，多项交付均已完成且没有未满足的阻塞依赖。输入不齐时停止验收，列出缺口；已有授权覆盖后续工作时由 Agent 选择匹配方法，否则请求所需决定，不要求用户为了形式重复调用 Skill。
4. 记录 Git 基准和已有工作区改动，避免把未完成、未归属或验收过程产生的文件误判为交付结果。
5. 整体验收发现需要修复时，先形成当前验收结论，再由 Agent 依据问题性质和既有授权选择修复方法；修复结果可以重新进入本验收方法检查。

## 判断是否适用

只有同时满足以下条件才继续：

- 存在已确认的整体目标、范围、规则和可观察完成标准；
- 结果由多项已完成任务、模块或交付组成，需要验证跨任务连接和组合用户路径；
- 当前请求或持续任务确实包含整体验收，而不是单项实现后的局部检查；
- 可以取得足以验证整体主张的实际成果和环境；
- 没有尚未完成或被阻断的前置交付。

任一条件失效时停止使用本方法并说明原因。单项改动由其实现或 Bug 修复方法完成相关验证；代码质量检查使用 `z-code-review`；发布目标冒烟使用发布方法。用户显式指定但不适用时，应用本节完成边界判断，不静默替换方法。

## 完成验收闭环

1. **建立矩阵**：把每项整体完成标准映射到可观察证据和具体检查，标出跨任务连接点、主要用户路径与高风险边界。
2. **取得新鲜证据**：复用各任务结果作为线索，但重新运行足以证明整体主张的测试、构建、静态、运行或数据检查；读取完整输出、退出状态和失败数量。
3. **验证组合行为**：实际执行端到端或跨模块路径，而不只重复单元测试。按产品形态检查适用的视觉、响应式、无障碍、性能、安全、兼容、迁移和恢复结果。
4. **处理主观结果**：审美、手感或业务接受度不能客观判定时，呈现真实产物、差异和风险，由用户作必要取舍；不把所有验收机械升级为确认点。
5. **分类发现**：
   - 规格内缺陷或遗漏使当前验收不通过。验收本身不授权修复；既有修改授权覆盖时，由 Agent 选择 `fix-bug`、`z-debug`、`z-implement` 或直接处理，修复后原验收目标仍有效时重新执行相关验收。
   - 规格外新能力单独记录，不扩大当前范围，也不阻止已确认规格通过。
   - 用户已接受的问题记录为限制、后续工作或验证盲区。
   - 关键前提被推翻时暂停验收，由 Agent 应用适合的产品、架构或技术设计方法，不能在验收中改写规格。
6. **形成结论**：逐项给出通过、未通过或等待用户判断的证据，说明执行过的检查、未解决问题和验证盲区。

## 完成条件

只有所有规格内完成标准都有本次新鲜证据、组合路径通过、未解决项已正确分类且必要主观结果获用户接受，才声明整体验收通过。验收结论不自动更新任务状态、创建提交、推送、创建 PR、合并、部署或发布；这些行动分别服从用户授权和项目约定。不创建额外关闭报告，除非项目已有唯一事实来源且当前授权明确要求更新。
