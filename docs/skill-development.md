# Skill 开发

本文面向 `z-skills` 的维护者，说明一个 Skill 从维护源码到运行副本的设计与验证约定。集合的用途、安装入口和现行 Skill 目录保留在根目录 [`README.md`](../README.md)；单个 Skill 的运行方法由它自己的 `SKILL.md` 定义。

Skill 的发现与调用机制参考 Codex 文档 [Build skills](https://learn.chatgpt.com/docs/build-skills.md)。

## 内容层次

| 层次 | 位置 | 职责 |
|---|---|---|
| 集合入口 | `README.md` | 说明项目定位，列出现行 Skills，并提供安装与调用入口 |
| 维护资料 | `docs/` | 记录项目级设计、研究和维护规则，不进入 Skill 的运行上下文 |
| 维护源码 | `skills/<skill-name>/` | 保存一个可独立验证和发布的 Skill |
| 运行副本 | `${CODEX_HOME}/skills/<skill-name>/` | 由明确安装动作产生，只用于实际调用，不反向定义维护源码 |

源码修改、安装、提交和发布是彼此独立的操作，需要分别执行和验证。

## 编写 Skill

### 设计约定

一个 Skill 应满足以下约定：

- **独立职责**：只负责一个范围清楚、可以验证的主要结果。
- **准确发现**：`name` 和 `description` 说明结果、适用情形与相近反例，让 Agent 能稳定判断是否使用。
- **按需组合**：提供专业方法，但不充当 Agent、工具、中央路由器或工作流引擎。
- **授权不扩张**：选择 Skill 不扩大用户授予的修改范围、外部影响或其他权限。
- **最小运行内容**：只保留模型不应临场重造的专业判断、知识和确定性操作。
- **可检查完成**：说明必要输入、停止情形和能够证明主要结果已经取得的证据。

同一规则只保留一个来源。跨 Skill 复用通过调用另一个 Skill 表达，不直接依赖其他 Skill 目录中的文件。

### 目录结构

```text
skills/<skill-name>/
├── SKILL.md                 # 必需：发现信息与执行核心
├── agents/
│   └── openai.yaml          # Codex 展示与调用元数据
├── references/              # 可选：条件知识、示例或分支说明
├── scripts/                 # 可选：需要一致结果的确定性工具
└── assets/                  # 可选：模板或交付资产
```

`SKILL.md` 是唯一规范必需文件。只有确有运行需要时才增加其他目录和文件，不创建空目录。

项目级研究与设计放在根目录 `docs/`。只属于单个 Skill 的维护资料可以放在该 Skill 的 `docs/`，但运行时内容不得依赖这些维护资料。

## 维护流程

### 1. 新建或升级

新建或升级只修改 `skills/` 中的维护源码：

1. 确定唯一主要结果，以及应触发和不应触发的代表性请求；
2. 明确必要输入、权限、副作用、停止情形和完成证据；
3. 编写或更新 `SKILL.md`，只在需要时增加 `references/`、`scripts/` 或 `assets/`；
4. 同步 `agents/openai.yaml` 中的展示信息和调用策略；
5. 更新根目录 README 的 Skill 目录；只有复杂用法才增加独立的人类文档。

历史版本和运行副本都不能作为当前维护源码。同名 Skill 也应从当前需求重新设计，而不是直接恢复旧实现。

### 2. 验证

每次新建或升级至少检查：

1. `SKILL.md` 的名称、描述、触发边界和主要结果一致；
2. `agents/openai.yaml` 与 `SKILL.md` 的调用方式保持同步；
3. 代表性正例、相近反例和默认值路径符合预期；
4. 新增或修改的脚本已经实际运行，并核对了输出；
5. 发布或安装后从目标位置重新校验，而不是只检查源码目录。

当前仓库尚未提供统一的集合级校验命令。使用的验证工具和无法覆盖的行为应在本次维护结果中说明。

### 3. 发布与安装

发布副本只包含实际存在的运行文件：

- `SKILL.md`
- `agents/`
- `references/`
- `scripts/`
- `assets/`

不要直接发布整个源码目录，也不要把 Skill 的维护 `docs/` 或项目级资料加入运行副本。安装时把验证后的发布副本放入 `${CODEX_HOME}/skills/<skill-name>`；未设置 `CODEX_HOME` 时通常使用 `~/.codex/skills/<skill-name>`。

安装目标已存在时，先确认其来源和本地改动再替换。安装完成后从目标位置重新校验，并在新的 Codex 任务中使用。
