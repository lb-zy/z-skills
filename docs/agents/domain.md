# 领域文档

工程 skill 探索代码库时，应按以下方式使用本仓库的领域文档。

## 探索前先读取

- 仓库根目录下的 **`CONTEXT.md`**，或者
- 如果仓库根目录存在 `CONTEXT-MAP.md`，则读取它；它会指向每个上下文对应的 `CONTEXT.md`。读取与当前主题相关的所有文件。
- **`docs/adr/`**：读取涉及即将工作的区域的 ADR。在多上下文仓库中，还要检查 `src/<context>/docs/adr/` 下与上下文相关的决策。

如果这些文件不存在，直接继续。不要特别指出它们缺失，也不要建议提前创建。domain-modeling skill 会在术语或决策真正确定后按需创建它们。

## 文件结构

这是一个单上下文仓库：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

## 使用术语表中的词汇

当输出中提到领域概念时，使用 `CONTEXT.md` 中定义的术语。不要改用术语表明确避免的同义词。

如果所需概念还不在术语表中，记录这一缺口并交给 domain-modeling skill 处理。

## 标记 ADR 冲突

如果输出与现有 ADR 冲突，应明确指出，而不是静默覆盖：

> _与 ADR-0007（事件溯源订单）冲突——但值得重新讨论，因为……_
