“内部接口”不意味着可以无契约变更。只要跨进程、可独立部署或由不同团队使用，就需要明确兼容性和责任人。

## 2. 契约优先

HTTP 接口使用锁定具体版本的 [OpenAPI Specification](https://spec.openapis.org/oas/latest.html)；本文档核对时的最新版本为 3.2.0，但项目应以已验证的工具链选择并锁定版本，不在构建中自动追随 `latest`。

契约必须能驱动以下至少一项：客户端/服务端验证、类型生成、契约测试、模拟适配器、兼容性检查或可发布文档。如果它只是一份不受检查的手写说明，它不是权威契约。

### 3.1 基本语义

- 资源和字段使用领域语言，不泄漏数据库表或框架类名。
- 状态码、缓存、条件请求、内容类型和重定向按标准 HTTP 语义使用，不所有结果都返回 `200`。
- 区分语法验证、未认证、无权、对象不存在、业务冲突、限流和服务故障。
- 数据类型、单位、枚举、时区、精度、可空性、缺失与显式 `null` 语义已写入 schema。

## 4. 错误契约

HTTP 错误优先使用 [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html) Problem Details。RFC 9457 已取代 RFC 7807。

| 字段 | 规则 |
|---|---|
| `type` | 稳定、可引用的问题类型 URI；客户端按它分支 |
| `title` | 问题类型的稳定摘要，不放具体敏感数据 |
| `status` | 当次 HTTP 状态 |
| `detail` | 对当次问题的人类可读说明，不作为程序分支条件 |
| `instance` | 当次问题的可追踪标识，不暴露内部路径 |
| 扩展字段 | 字段错误、原因码、可重试时间等结构化数据，在契约中定义 |

| 问题类型 | 何时发生 | HTTP 状态 | 扩展字段 | 客户端行动 | 日志/告警 |
|---|---|---|---|---|---|
| [URI/稳定代码] | [填写] | [填写] | [填写] | [修正/重试/联系] | [填写] |

不在错误响应中返回堆栈、SQL、内部主机、令牌、用户是否存在等不必要信息。

按 [OWASP API Security Top 10:2023](https://owasp.org/API-Security/editions/2023/en/0x11-t10/) 检查对象级授权、属性级授权、功能级授权、资源消耗、业务流程滥用、服务端请求伪造、资产清单和不安全第三方集成。

## 8. 版本、兼容性与废弃

| 变更 | 兼容性 | 检测方式 | 消费者迁移 | 双运行期 | 停用信号 | 删除条件 |
|---|---|---|---|---|---|---|
| [增加字段/枚举/语义变更] | 兼容/破坏 | [schema + 消费者契约] | [填写] | [填写] | [header/日志/通知] | [无流量 + 日期 + 批准] |

- 只在无法通过兼容演进解决语义变更时增加主版本，不为每次发布创建 API 版本。
- “新增可选字段”也可能破坏严格客户端；兼容性结论必须由真实消费者契约验证。
- 废弃计划包含所有者、消费者清单、代替方案、日期、使用量和强制停用条件。
