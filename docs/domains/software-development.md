# 软件开发 Skill 集设计

本文记录软件开发 Skill 集的确定设计。正式存在的 Skill 以根目录 [`README.md`](../../README.md) 和 `skills/` 中的维护源码为准。

通用开发规则见 [`skill-development.md`](../skill-development.md)。

## 目标

为软件需求分析、设计、实现、验证和发布提供可独立安装的专业 Skills。集合不提供中央路由器或固定生命周期；Agent 根据当前任务选择必要能力。

- 所有 Skill 使用 `z-` 前缀，名称直接表达动作或结果。
- 每个 Skill 只承诺一个可观察的主要结果，并说明触发、反例和完成证据。
- 每个 Skill 可独立使用；组合时传递普通输入和产物，不依赖固定调用链。
- 简单任务由 Agent 直接完成，不为覆盖生命周期而强制使用 Skill。

## 软件开发阶段

阶段用于浏览能力和检查覆盖面，不是固定调用顺序。单项任务可以跳过不需要的阶段，同一 Skill 也可能服务多个阶段。

| 阶段 | 目标 | Skills |
|---|---|---|
| 需求发现 | 核实输入，确定产品规则和领域含义 | `z-triage`、`z-product`、`z-model-domain` |
| 方案设计 | 确定界面、模块责任、技术方案并验证关键取舍 | `z-ui-design`、`z-architecture`、`z-tech-design`、`z-prototype` |
| 规格与计划 | 收敛共同依据并形成纵向交付任务 | `z-spec`、`z-tasks` |
| 实现 | 用可验证切片完成软件改动 | `z-tdd`、`z-implement` |
| 评审与验收 | 检查代码改动和组合后的软件成果 | `z-code-review`、`z-verify` |
| 发布 | 将已验收成果送达真实目标并验证 | `z-release` |
| 维护与改进 | 修复缺陷、诊断疑难问题并调查改善候选 | `z-fix-bug`、`z-debug`、`z-improve` |

### 跨阶段能力

| Skill | 作用 |
|---|---|
| `z-clarify` | 解决会改变目标、范围、行为或验收依据的关键歧义 |
| `z-research` | 核对当前工作依赖的代码库外客观事实 |
| `z-explore` | 为包含多个相互依赖未知的大型目标推进决策 |
| `z-handoff` | 为必须更换上下文的未完成任务保存最小恢复信息 |

## 关键边界

| 相邻能力 | 区分 |
|---|---|
| 产品、领域、界面、架构、技术设计 | 依次处理产品规则、领域含义、交互呈现、长期模块与数据责任、当前任务的实现决定，不互相代做 |
| `z-spec` 与 `z-tasks` | 前者收敛多项交付共享的决定，后者只把已确认规格切成纵向成果 |
| `z-fix-bug` 与 `z-debug` | 前者处理预期明确且可稳定复现的缺陷；未知、间歇、性能或首次修复失败的问题进入后者 |
| `z-code-review`、`z-verify` 与 `z-release` | 分别检查指定代码改动、组合后的软件成果、真实发布目标 |
| `z-tdd` 与任务级能力 | `z-tdd` 只负责一个行为切片的测试先行内循环，不声明整项实现或修复已经完成 |
| `z-triage` 与 `z-improve` | 前者整理尚未成为当前任务的外部输入，后者调查代码库内部改善候选，默认都不实施改动 |
