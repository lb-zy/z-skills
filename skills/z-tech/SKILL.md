# 技术设计

本 Skill 设计到实现者无需重新推导关键技术决定为止，不把小任务扩成正式技术文档。它只处理当前实现问题，并把决定交给 Agent 用于整体任务；不扩大文件修改、正式实施或发布授权。

开始设计前综合完整对话，确认主要请求、已确定的产品规则、系统边界和完成标准。目标或范围仍有关键歧义时，由 Agent 应用 `z-clarify`；共同理解获用户确认前不形成正式技术方案。

## 从真实系统出发

1. 读取任务、相关规格与设计、项目说明、代码、测试、ADR、配置和可用运行信号。
2. 明确需求到现有模块和行为的对应关系，以及必须保持的兼容约束。
3. 需要模块、接口或测试接缝判断时读取 [`../_shared/codebase-design.md`](../_shared/codebase-design.md)。
4. 产品规则失效时，建议 Agent 应用 `z-product`；系统边界不成立时，建议应用 `z-architecture`。只询问无法从事实取得且会阻碍设计的决定。

## 按风险覆盖

只展开与当前任务有关的角度：

- 组件责任、控制流与数据流；
- 接口、状态、不变量和权限；
- 重复、乱序、并发、幂等和事务边界；
- 失败如何检测、重试、隔离、补偿或恢复；
- 安全、隐私和秘密处理；
- 日志、指标、追踪与审计；
- 测试接缝、关键场景和故障注入；
- 迁移、兼容、启用、回退与不可逆变化；
- 至少一个真实替代方案及拒绝理由。

例如支付回调必须核对渠道合同，再决定唯一事件键、冲突载荷处理、状态转换、响应与重试语义；不能凭惯例发明状态码或默认引入队列。

## 产物与结束

小任务可在对话或交付任务中记录简短决定；多会话工作把共同依赖的决定写入规格。说明采用方案、关键流程、接口与状态、失败处理、验证策略、迁移和回退，以及仍待实现时核实的事实。

产物描述决定和约束，不写逐文件步骤、完整代码、固定模板、追踪矩阵或图文双份流程。难逆、无法从代码理解原因且经过真实取舍的技术决定，读取 [`../_shared/decision-recording.md`](../_shared/decision-recording.md)，由 Agent 在已有修改授权时记录 ADR。实现者能够在真实代码中直接行动，且高风险失败路径已有处理时结束；Agent 将技术决定整合到当前任务。
