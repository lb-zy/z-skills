# 探索大型决策

本 Skill 提供把大型模糊目标从未知关系梳理推进到决定足以形成共享规格的方法。探索产物是决定与证据，不是产品代码或交付任务。

## 建立决策地图

1. 用一句话写出目的地：谁将在什么条件下获得什么结果。
2. 判断是否确有多个相互依赖重大未知。普通大功能、明确重构或单一产品取舍不适用时立即退出，把控制权交回 Agent 选择更短路径。
3. 列出已确认决定、重大未知、它们之间的依赖、当前假设和明确范围外事项。
4. 把未知拆成能够产生一个决定的决策问题，不按前端、后端、数据库、团队或文件拆分。
5. 将地图保留在当前对话；只有工作确需跨会话且已有对应写入授权时，才写入项目现有唯一事实来源或一份本地决策文档，二者只选一个。

## 推进决定

每次选择一个无阻塞依赖且最能缩小后续空间的问题，并由 Agent 按问题性质应用合适的 Skill：

- 用户目标或关键歧义使用 `z-clarify` 或 `z-product`；
- 外部事实使用 `z-research`；
- 必须运行、操作或观看的问题使用 `z-prototype`；
- 术语和领域关系使用 `z-model-domain`；
- 界面、架构或技术问题使用对应 Skill。

被应用的 Skill 继承当前目标、范围和授权。Agent 将局部决定整合回决策地图；每次只记录决定、证据、仍成立假设和对地图的影响，不夹带正式实现，不要求标签、领取、分支或一会话一任务。

## 结束条件

当目标、范围、关键规则、必要设计方向、整体完成标准和主要风险足以形成共同建设依据，且剩余未知可以在有界交付内解决时，汇总稳定决定并结束探索。

原请求已经包含形成规格时，Agent 可以随后应用 `z-spec`；否则只交付决策地图、稳定决定和建议下一步。地图保留为证据而不成为第二份规格，不自动拆任务或开始编码，也不要求用户为了形式重复输入 `$Skill`。
