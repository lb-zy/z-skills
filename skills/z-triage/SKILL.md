# 分流外部输入

本 Skill 提供把外部输入整理到足以选择处理方法的程度。默认只读，不维护固定标签状态机，不扩大外部平台写入、代码修改或后续实施授权。

## 处理输入

1. 读取完整正文、附件、评论和相关历史，不根据标题或关键词分类。
2. 使用领域概念查找重复项；相同症状但不同根因不能仅凭表面相似合并。
3. 核对能从代码、文档或公开事实验证的基本主张，并区分已证实事实、未证实判断和报告者陈述。
4. 避免重复询问已有信息；缺少内容时只补齐会改变分类或风险等级的部分。
5. 安全问题先限制敏感信息传播，不在公开记录中索取秘密、真实个人数据或完整敏感载荷。

Bug 至少整理环境与版本、复现步骤、实际结果、预期结果、频率和影响范围。外部代码改动还应整理来源、目标、改动范围、可信边界和声称的验证。

## 分类与返回

- **可稳定复现的明确 Bug**：建议 Agent 应用 `fix-bug`；原因未知、间歇、性能回归或已有修复失败时建议应用 `z-debug`。
- **功能请求**：根据规模和未决问题返回 Agent，由 Agent 选择澄清、设计、规格或实现路径。
- **使用问题**：证据足够时可直接答复；暴露产品缺陷时重新分类。
- **外部代码改动**：整理目标、来源和风险后建议 Agent 应用 `z-code-review`，不在分流中完成正式评审。

用户直接要求实现、修复、设计或改善代码库时，这不是待分流的外部输入；应用边界判断后退出，让 Agent 处理原请求，不静默把直接要求改写为外部条目。

## 输出与授权

报告分类、重复关系、已核实证据、缺失信息、风险和推荐入口，然后把控制权交回 Agent。只有用户明确要求修改具体外部条目，或当前持续任务已有对应外部写入授权时，才评论、改状态、加标签或关闭条目；分类获确认、调用 `$z-triage` 或拥有代码修改授权均不能代替外部写入授权。
