# Skill Creator 引导

把用户的简短意图整理成完整创建简报，然后交给系统 `$skill-creator` 执行。不要自行重复 Skill 的初始化、编写、元数据生成或结构校验。

## 补全简报

优先从当前请求、对话、工作区和现有文件推断以下内容：

- 操作是新建还是升级；
- Skill 的唯一主要结果；
- 目标维护来源和绝对源码目录；
- 应触发的代表性请求；
- 相近但不应触发的请求；
- 必要输入、输出和完成证据；
- Agent 不应临场重造的专业判断、知识或确定性操作；
- 可能需要的 `references/`、`scripts/` 或 `assets/`；
- 需要保留的现有行为和用户改动。

先确定目标 Skill 的维护来源；部署副本只作为冲突证据，不作为修改来源。新建前检查该维护来源中的现行 Skills；当前会话已提供系统、用户或插件 Skill 元数据时，也检查是否已有相同职责。发现重叠且会改变目标时，向用户说明并取得选择。无法可靠确定目标绝对路径，或其他缺失信息会产生实质不同的 Skill 时，只提一个最关键的问题；否则使用证据支持的合理默认值继续。

## 加入研究要求

用户要求参考网上 Skill，或存在陌生领域、现行平台规范或活跃同类实现且研究很可能避免职责或兼容性错误时，在简报中要求 `$skill-creator`：

- 优先读取当前官方 Skill 规范；
- 选择少量仍在维护且职责相近的公开实现；
- 记录 URL、获取日期、版本或 commit，以及许可证；
- 比较触发边界、核心方法、资源组织和验证方式；
- 只提取适用的设计模式，不照抄不兼容或过时内容；
- 网络或可靠参考不可用时明确限制，并继续依据用户需求创建。

普通提示词封装、局部调整或已有充分一手依据时，不为完整感强制联网研究。

## 编译提示词

按以下结构生成一份自包含提示词。省略不适用的项目，不保留空占位符。

```text
使用 $skill-creator {创建|升级} <skill-name>。

目标维护来源：<源码仓库或受维护的 Skill 根目录>
目标源码：<绝对路径>
主要结果：<一个可观察结果>

触发情形：
- <代表性请求或上下文>

不应触发：
- <相近反例>

输入、输出与完成证据：
- <必要约束>

专业内容与资源：
- <模型不应临场重造的内容>

现有行为与兼容要求：
- <升级时必须保留的能力和当前用户改动>

外部研究：
- <适用时加入研究要求>

实现与验证：
- 保持 SKILL.md 精简，只创建确实需要的资源。
- 同步 agents/openai.yaml。
- 实际运行新增或修改的脚本。
- 运行平台结构校验。
- 至少用代表性正例、反例和默认值路径检查行为边界。
- 对新颖、复杂或重大升级的 Skill，在环境支持且风险可接受时，使用不泄露预期答案的真实请求进行独立前向测试；无法执行时报告限制。
- 把测试产物放入明确的临时目录，检查后清理，不在目标源码外留下持久改动。
- 报告创建或升级结果、验证证据和剩余限制。

除可清理的临时测试产物外，只修改目标 Skill 的维护源码。安装、提交和发布不在本次范围内。
```

## 调用 Creator

提示词完整后，加载并遵循系统 `$skill-creator`，把编译后的提示词作为本次创建或升级请求继续执行。除非用户明确只要求提示词，否则不要停在展示提示词；完成条件是 `$skill-creator` 已实现并验证目标 Skill。

若系统 `$skill-creator` 不可用，停止并说明缺少的依赖，不自行复制它的实现流程。
