# UI 设计

## 确认交付分支

把当前交付限定为 UI 评审、设计方案或交互原型中的一个分支。用户请求多项交付时，按顺序逐项确认和完成；请求原型但尚无已确认方案时，先完成设计方案分支。

1. 读取相关规格、截图、设计系统和实现，区分事实、假设及需要用户决定的产品问题。当前分支唯一确定，且每项相关输入均已分类后继续。
2. 明确范围、主要用户、核心任务、目标平台与尺寸、期望结果和必要约束。只询问会改变交付的问题，持续到不存在未决的语义决定。
3. 展示当前分支、输入、交付物、范围外事项、完成证据、检查方法、执行方式和副作用，等待用户明确确认。以用户看到完整约定后的回复作为确认；确认只授权约定中的当前分支和副作用。

## UI 评审

1. 读取完整的 [评审标准](references/review-rubric.md) 和与产品类型对应的 [产品模式](references/product-patterns.md)。
2. 按评审标准的取证与评审顺序，检查确认范围内的真实界面、相关状态和目标尺寸。每个确认项都有界面证据或“未验证”标记后继续。
3. Web 界面可运行且依赖可用时，使用 `scripts/capture-ui.mjs` 固定视口取证，使用 `scripts/audit-ui.mjs` 定位可访问名称、标签、溢出和基础交互问题；把工具未覆盖的检查保留为人工评审。
4. 按评审标准的发现格式与交付顺序报告。每个确认的核心任务、状态和目标尺寸均有结论或“未验证”标记后，UI 评审分支完成。

## 设计方案

1. 读取完整的 [设计方法](references/design-method.md) 和与产品类型对应的 [产品模式](references/product-patterns.md)。
2. 按设计方法从核心任务推导一套推荐方案；只有实质取舍需要用户决定时才比较候选。发现新的产品决定时，返回交付分支确认。
3. 按设计方法的“形成可评审结果”交付方案并等待确认。每个确认的核心任务、相关状态和目标尺寸均已设计，且假设、取舍与验证条件完整后，用户的明确确认完成设计方案分支。

## 交互原型

1. 在设计方案已确认且用户明确选择交互原型分支后，读取完整的 [设计方法](references/design-method.md)、与产品类型对应的 [产品模式](references/product-patterns.md) 和 [原型验收](references/prototype-qa.md)。
2. 在生产项目外使用模拟数据制作独立原型，只实现确认范围所需的页面、交互和状态。发现会改变已确认方案的决定时，返回交付分支确认。
3. 按原型验收的检查矩阵逐项验证，修正范围内的失败项并重新检查。
4. 交付原型，并把每项通过条件标为“通过、失败、未测试”。范围内可执行的条件全部通过、限制已有具体记录，且用户明确确认后，交互原型分支完成。
