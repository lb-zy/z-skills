# 界面与交互设计

本 Skill 先让用户任务清楚、状态完整，再确定视觉表达。沿用项目已有设计系统和交互惯例，除非当前目标明确要求改变。只交付界面决定，不因设计请求获得正式代码、文件写入或发布授权。

开始设计前综合完整对话，确认主要请求、目标用户、任务结果和界面范围。目标、范围或验收依据仍有关键歧义时，由 Agent 应用 `z-clarify`；共同理解获用户确认前不形成正式界面方案。

## 理解任务

1. 读取产品规则、现有界面、设计规范和接近真实密度的内容。
2. 明确主要用户、任务、对象、动作范围、后果和可逆性。
3. 动作资格、权限或业务后果不明确时，建议 Agent 应用 `z-product`，不要用界面选择暗自决定规则。
4. 把首屏重点、主要动作、次要信息和详情层级按用户判断顺序排列。

## 设计交互

- 为动作选择熟悉且与语义匹配的控件；工具使用图标，模式使用分段控件，布尔设置使用开关或复选框，数值使用输入、步进或滑杆。
- 让动作范围、当前对象、进行中状态、成功结果、失败恢复和破坏性后果清楚可见。
- 以完成主任务所需的最小干预为准，不用说明文字弥补含糊交互。
- 需要验证手感、动效或复杂状态切换时，由 Agent 应用 `z-prototype`，以实际操作结果决定。

## 覆盖界面状态

按当前功能检查适用状态：首次加载、局部加载、无数据、筛选无结果、陈旧或部分失败、全局错误、无权限、操作中、成功、失败与可重试。不要把“没有内容”和“请求失败”设计成同一结果。

响应式设计必须说明信息优先级如何变化，不只是缩小桌面布局。使用真实超长名称、极大或极小数值、窄屏和宽屏检查稳定尺寸、换行、溢出、遮挡和动作可达性。

键盘与屏幕阅读器应能完成主路径；焦点顺序、名称、状态变化、错误关联和对比度必须可验证。

## 视觉方向与产物

视觉应匹配产品领域：运营工具安静、密集且便于扫描；内容或品牌页面可以更有表现力。明确字体层级、密度、颜色角色、图标、间距、媒体和动效原则，避免模板化卡片堆叠或与任务无关的装饰。

输出用户任务、信息结构、关键操作、状态矩阵、响应式变化、视觉方向、无障碍要求、真实内容例子和需要验证的场景。结果足以让后续规格或实现不重新推导关键界面决定时结束；不要启动开发服务器或编写正式代码。
