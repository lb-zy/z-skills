# 原型验收

原型用于验证已确认的设计判断，不以页面数量或视觉效果作为完成标准。

## 验收准备

- 写明要验证的任务、目标视口、代表性内容、模拟数据和不在范围内的能力。
- 为每个任务定义起点、成功结果和可观察的通过条件。
- 原型保持独立，不连接真实服务、不写入生产数据。

## 检查矩阵

- **任务流**：主要路径可从起点完成；下一步、返回、取消、撤销和完成结果明确。
- **状态**：按任务覆盖加载、空、无结果、校验失败、权限不足、网络失败、处理中、禁用和成功状态。
- **响应式**：在确认尺寸逐一检查导航、主要内容、固定控件、弹层和软键盘；用长标题、长值、空值和多项目测试溢出。
- **键盘**：焦点顺序符合视觉顺序；焦点可见；Enter、Space、Escape 和方向键按控件语义工作；弹层关闭后焦点返回触发点。
- **无障碍**：交互元素有准确名称和语义；标签与错误关联；状态变化可被感知；颜色不是唯一线索；动效尊重减少动态偏好。
- **视觉一致性**：字体、色彩角色、间距、边框、图标和状态反馈遵循同一规则；动态内容不引起无关布局位移。

## Web 取证

从能解析依赖的项目或工具目录调用 Skill 内脚本；需要 Node.js 18+ 和 Playwright，`axe-core` 可扩展自动化无障碍规则检查。依赖缺失时报告前置条件；只有用户明确授权依赖变更后才安装。

```bash
Z_UI_SKILL_DIR="/absolute/path/to/z-ui-design"
node "$Z_UI_SKILL_DIR/scripts/capture-ui.mjs" http://127.0.0.1:3000 --out artifacts/ui
node "$Z_UI_SKILL_DIR/scripts/audit-ui.mjs" http://127.0.0.1:3000 --out artifacts/ui/audit.json
```

用 `--viewport name:WIDTHxHEIGHT` 重复指定目标尺寸。CI 可为审计增加 `--fail-on P1`。脚本结果用于定位，不代替键盘操作、任务流和视觉判断。

## 交付结果

对每项通过条件标记“通过、失败、未测试”，附截图、复现步骤或审计记录。失败项修正后重新检查；无法验证的能力单独列出，不算作通过。
