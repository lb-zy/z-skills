# 设计方法

从用户任务推导界面，不从流行风格或组件清单出发。

## 建立设计依据

- 写清主要用户、核心任务、使用频率、风险、环境和目标设备。
- 以现有产品、设计系统、品牌规范和真实内容为事实来源。
- 将缺失信息标为假设或待决策项；会改变业务行为的问题交还用户。

## 推导方案

1. **信息架构**：围绕用户认识的对象、动作和状态分组，优先支持主要任务；导航名称使用领域语言。
2. **任务流**：先画最短成功路径，再补充加载、空、无结果、校验失败、权限不足、网络失败、处理中、成功和撤销等相关状态。
3. **布局层级**：让当前任务、关键状态和下一步动作先被看到。根据使用频率和比较需求决定密度，不把页面机械拆成卡片。
4. **响应式行为**：说明每个关键区域在目标尺寸下是保留、折叠、重排、替换还是移除；不能只把桌面布局缩小。
5. **交互模型**：为命令、模式、选择和数值使用合适控件；保持位置稳定，提供即时反馈、取消或恢复路径，并覆盖键盘操作。
6. **视觉系统**：从产品语境和品牌推导字体、色彩角色、间距、边框、层级与动效。选择一个有依据的识别特征，不套用固定渐变、圆角卡片或装饰套路。
7. **界面文案**：使用代表性真实内容；标签描述对象或动作，错误信息说明原因和下一步，不用界面文字讲解设计本身。

## 形成可评审结果

交付内容按需包括：

- 推荐方案及其依据；
- 结构、关键任务流和页面状态；
- 关键屏幕在目标尺寸下的布局与行为；
- 必要的设计令牌或组件规则；
- 已确认事实、假设、取舍和待用户决定的问题；
- 验证任务、测试尺寸和通过条件。

提交前自检：方案是否直接改善核心任务，是否依赖未确认的产品决定，是否遗漏失败或恢复路径，是否能通过具体任务而不是审美偏好验证。
