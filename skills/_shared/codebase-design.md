# 代码库设计参考

只在模块边界、接口、测试接缝或可替换依赖成为当前问题时读取。本文件不是可调用 Skill。

## 核心语言

- **模块**：具有接口和内部实现的任意尺度代码单元，可以是函数、类、包或跨层纵向能力。
- **接口**：调用者必须知道的全部内容，包括输入输出、约束、顺序、错误、配置和性能特征，不只是一段类型签名。
- **接缝**：能够替换行为而不修改调用处的位置，也是接口所在的位置。
- **适配器**：在接缝处满足接口的具体实现。
- **深度**：调用者学习少量接口即可获得大量能力。深模块隐藏复杂度，浅模块只是转发复杂度。

## 设计判断

1. 优先让接口更小、更稳定，把变化、规则和故障处理集中到模块内部。
2. 做删除测试：删除模块后，复杂度若散回多个调用者，模块在提供价值；复杂度若一起消失，它可能只是转发层。
3. 调用者和测试应跨越同一公共接缝。测试必须穿透接口检查内部状态时，重新评估接缝位置。
4. 只有一个真实实现且没有测试替身需要时，不为假想未来引入适配器；生产实现与必要测试替身同时存在时，接缝才有现实价值。
5. 接受依赖而不是在模块内部偷偷创建；返回可观察结果，把不可避免的外部副作用隔离在明确边界。

## 依赖与测试

- **进程内计算**：直接通过模块接口测试，不增加适配器。
- **本地可替代依赖**：优先使用真实的轻量替身，例如内存文件系统或测试数据库。
- **自有远程服务**：把传输放在适配器中，业务规则留在深模块，测试使用本地适配器。
- **真实第三方服务**：在外部边界使用最小端口，mock 该边界而不是内部协作者。

建立新接缝后，用接口级行为测试替代已经失去价值的内部测试，不把新测试叠加成重复保护。比较替代设计时，至少评估接口大小、调用者负担、变化局部性、错误责任和迁移成本；不要默认采用第一个方案。
