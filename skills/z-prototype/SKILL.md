# 用原型验证

本 Skill 提供先确定问题、再决定原型形态的验证方法。一个原型只承担足以回答当前问题的内容，观察结果由 Agent 整合到整体任务；本方法不把创建原型的授权扩大为修改正式产品或发布授权。

综合完整对话确认主要请求、具体验证问题和判断标准；存在会改变原型方向的关键歧义时，由 Agent 应用 `z-clarify`，共同理解获用户确认前不制作原型。

只有用户明确要求制作原型，或当前持续任务已经授权创建验证产物时才写入原型代码。只读请求只说明建议验证的问题、形态和判断标准，不创建、归档或删除文件。

## 定义验证

1. 写出一个具体问题、代表场景和可观察判断标准。
2. 选择最小形态：逻辑原型、交互原型、视觉原型或三者必要组合。
3. 使用项目已有技术和最少依赖；明确标记一次性，默认使用内存或假数据，不连接生产系统。
4. 只有真实取舍需要比较时才制作多个变体，不能为了展示而固定生成三套方案。

## 制作与试跑

- 让状态、输入、输出和错误可见，并提供一条明确运行方式。
- 逻辑问题覆盖合法、非法、重复、乱序和关键不变量。
- 交互问题执行真实代表任务，包括取消、失败、键盘或触控等会改变结论的场景。
- 视觉问题使用接近真实密度和极端长度的内容，不用空壳布局得出结论。
- 客观行为由 Agent 实际运行并记录证据；手感、审美等主观结果交给用户最终判断。

## 结论与清理

报告原问题、原型位置与运行方式、执行过的场景、观察证据、结论、限制和产生的决定。只有当前任务包含对应修改授权时，才把稳定决定写回原设计或规格，并删除或归档已提取结论的一次性代码和截图；否则只报告建议回写与清理的内容。

原请求已经包含正式实施授权时，Agent 可以在本 Skill 完成后应用 `z-implement` 或匹配方法；否则只交付验证结论和可能的下一步。正式实现必须依据已确认决定重新实现并验证，不要直接搬运未经产品标准检查的原型代码。
