# 修复可复现 Bug

本 Skill 提供简单 Bug 从复现到本地可交付的完整修复方法。Agent 始终是执行者；本方法不扩大目标、修改授权或发布授权。

## 核对边界

1. 结合完整对话、项目规则、现有代码与工作区状态，复述本次缺陷的实际结果、预期结果、复现条件和范围。
2. 将 Skill 调用与行动授权分开判断。用户明确要求修复或当前任务已有持续修改授权时才修改项目；仅写出 `$fix-bug`、确认理解或确认方案，只指定方法，不单独构成修改授权。
3. 修改授权不足时保持只读，只报告当前能确认的事实和修复所需的明确授权。修复授权不包含提交到远端、创建 PR、合并、部署或发布。
4. 只有会改变目标行为、范围或验收依据的缺口才由 Agent 应用 `z-clarify`；共同理解确认前不修改项目。能够从代码和环境查明的事实自行核对。
5. 需要其他专业方法时，由 Agent 根据当前证据选择并整合。被应用的 Skills 继承当前目标、范围、修改授权和验证要求，只处理各自适用的问题。

## 判断是否适用

只有同时满足以下条件才继续：

- 预期行为足够明确；
- 能用确定步骤、现有失败检查或一个可建立的回归测试稳定观察问题；
- 问题范围足够小，能够在一次有界检查中定位并修复；
- 没有性能退化、间歇失败、并发时序、生产环境专属或此前修复失败等疑难信号。

无法稳定复现、经过一次有界检查仍不能形成可证伪的根因假设，或修复首次未解决原始症状时，立即停止使用本方法。明确说明 `fix-bug` 不再适用；原修复授权仍覆盖后续诊断时，由 Agent 改用 `z-debug`，否则只报告下一步所需授权。

## 完成修复闭环

1. **保护现场**：记录版本、相关配置、Git 基准和已有工作区改动，只处理本次缺陷，不覆盖或混入他人改动。
2. **建立基线**：按用户路径实际复现问题，保存失败命令、测试或可观察证据。证据捕获的必须是用户所述症状，而不是附近的另一个失败。
3. **建立回归保护**：代码行为适合自动化时，由 Agent 应用 `z-tdd`，先取得因目标缺陷而失败的红灯；视觉、配置或文档缺陷改用与成果匹配的可重复证据，不为形式制造测试。
4. **实施最小修复**：根据证据修复根因，只改完成当前行为所需内容。若证据推翻简单 Bug 判断，按适用边界退出，由 Agent 改用 `z-debug`。
5. **验证结果**：运行回归检查到绿色，重跑原始复现路径，再按改动风险扩大到相关测试、静态、构建、视觉或实际运行检查。读取完整输出并区分本次回归与既有失败。
6. **质量评审**：由 Agent 应用 `z-code-review`，分别检查要求符合度和工程质量；修复所有阻断交付的问题，并重跑受影响验证。
7. **交付结果**：报告根因证据、实际改动、执行过的检查及结果、未解决问题和验证盲区。只有证据支持时才声明修复完成。

## 完成条件

只有原始症状已经消失、目标行为有回归保护或等价证据、相关风险检查通过、评审没有未解决的阻断问题，并且所有验证盲区均已如实说明，本次修复方法才算完成。是否提交由当前项目约定与用户授权决定；任何外部发布都属于独立行动。
